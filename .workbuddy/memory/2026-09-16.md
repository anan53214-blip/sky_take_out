## 套餐分类下拉框只显示 2 个的排查
- 现象：套餐管理页"套餐分类"下拉只有 人气套餐 / 商务套餐，用户以为漏写了查询接口。
- 结论：**不是 bug**。category 表靠 `type` 区分：1=菜品分类，2=套餐分类。前端按页面传参：菜品管理页 `type=1`，套餐管理页 `type=2`。服务端 `CategoryController.list(Integer type)` 无默认值，不传则返回全部 status=1 的分类。
- 后端链路：`/admin/category/list?type=2` → CategoryController.list → CategoryServiceImpl.list → CategoryMapper.xml `<select id="list">`（`where status=1 and type=#{type}`，写死了 status=1，禁用分类不会出现在下拉框）。
- 本库 category 实际数据：type=2 仅 id=13 人气套餐、id=15 商务套餐；其余 8 条为 type=1。
- 排查方法：直接 `select id,type,name,sort,status from sky_take_out.category;` 或用浏览器 Network 看请求 Query 参数。

## SetmealServiceImpl.update 复用批量删除 + Java 版本坑
- 原代码 `setmealDishMapper.deleteBySetmealId(id)` **编译不过**：SetmealDishMapper 里没这个方法，只有 `deleteByIds(List<Long> setmealIds)`（XML：`delete from setmeal_dish where setmeal_id in (...)`）。
- 结论：单条删除不新建方法，复用批量 `deleteByIds(Collections.singletonList(setmealDTO.getId()))`，单元素 IN 合法。
- **版本坑**：项目语言级别 = Java 8（pom 未指定 java.version，继承 spring-boot-starter-parent 2.7.3 默认 1.8；已编译 class 均为 major 52）。**不能用 `List.of` / `Set.of` / `Map.of`（Java 9+）**，Java 8 等价写法：`Collections.singletonList(x)` / `Arrays.asList(x)`。
- 已顺带修正：去掉 `List.of` 写法并 import `java.util.Collections`。

## 套餐起售/停售的状态语义（易误解，非 bug）
- 现象：套餐状态列显示"起售"(1)，点操作列"停售"按钮，请求却是 `/api/setmeal/status/0?id=44`，用户以为状态传反了。
- 结论：**不是 bug**。`POST /admin/setmeal/status/{status}?id=xx` 路径里的 status 是**目标状态**（点完要变成的状态），不是当前状态。
  - 起售中(1) → 按钮"停售" → 传 0（改成停售）
  - 停售中(0) → 按钮"起售" → 传 1（改成起售）
- 后端链路：`SetmealController.setStatus(@PathVariable Integer status, Long id)` → `SetmealService.setStatus(id,status)` → 直接用传入 status 构建 Setmeal 更新，传什么存什么。
- 备注：截图里 `status/0` 是 URL 路径参数（path variable），不是"请求头"。

## Day04 套餐管理：用户实现 vs 指南参考答案 对比
- 指南 day04（`/d/sky-take-out-info/day04/项目实战-套餐管理 - 参考答案.md`）含 5 功能：新增/分页/删除/修改/起售停售。用户 5 个功能都实现，编译通过。
- 🔴 功能缺失：`SetmealServiceImpl.setStatus` **没有"套餐内包含停售菜品则不能起售"校验**（指南第5节核心需求）。需注入 DishMapper + 新增 `getBySetmealId`；`SetmealEnableFailedException` 异常类**已存在**（sky-common/.../exception/），`SETMEAL_ENABLE_FAILED` 常量也已存在，无需新建。
- 🔴 潜在 NPE：`update()` 里 `setmealDishMapper.insert(setmealDishes)` 写在判空 `if` **外面**（第127行判空设 id，第132行 insert 在 if 外）→ setmealDishes 为 null 时 NPE。应把 insert 移进 if 内。
- 🟡 规范不足：① `delete`/`update`/`setStatus` 缺 `@Transactional`（跨多表应加，指南都有）；② `delete` 用魔法数 `status()==1` 而非 `StatusConstant.ENABLE`（insert 已用常量，不一致）；③ `SetmealController.delele` 方法名拼写错（应为 delete）；④ 方法命名 `insert/delete/setStatus` 与指南 `saveWithDish/deleteBatch/startOrStop` 不统一（功能无影响）。
- ✅ 优于指南：`insert` 显式 `setStatus(StatusConstant.DISABLE)` 默认停售（指南依赖 DB 默认）；`insert`/`update` 对 setmealDishes 判空；`delete` 用批量 IN 删除比指南逐条删高效。
- SetmealMapper.xml 分页用 `order by s.update_time desc`（指南用 create_time，差异无功能影响）。
